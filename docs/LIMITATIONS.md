# Limitations

The honest ledger: everything shannon-autograd — an **experimental** research
prototype — does **not** do (or does with a caveat), sourced from deviations, pitfall
rows, and `KNOWN WART` comments recorded during development. This is not a
roadmap — that's [ROADMAP.md](../ROADMAP.md); the "Planned fix" column links
the two. Read this table *before* the symptom column reads you.

| # | Limitation | Symptom you'd hit | Workaround today | Planned fix | Source |
|---|---|---|---|---|---|
| 1 | **Raw-launch hole in the tape's borrow guarantee.** Borrows statically freeze taped buffers against `&mut`, but a raw `launch!` of a const-ref *scatter* kernel (GradSink atomics) aliasing a taped buffer compiles fine — and corrupts backward. | Silently wrong gradients, no error, no crash. | Convention: between the first `record` and `backward`, touch taped buffers only through `ops::` calls and read-only launches; untaped queries go inside `tape.pause()`. | Kernel registry + ambient-recording tape / compile-time verifier ([ROADMAP](../ROADMAP.md) Phases 2 and 5). | internal design notes, pitfall 6 |
| 2 | **Bare `cargo oxide build` compiles for a fixed default architecture — and `cargo oxide run`'s arch auto-detection silently falls back to that default when `nvidia-smi` is not on `PATH`** (found during the release fresh-shell rehearsal: login shells without WSL2's `/usr/lib/wsl/lib` hit this even via `run`, while `cargo oxide doctor` still reports the GPU fine — it detects via the driver API instead). | CUDA error 218 ("a PTX JIT compilation failed") at the first launch on any GPU whose architecture differs from the build default. Bit us repeatedly during development. | Use the README quickstart's `PATH` export verbatim (it includes `/usr/lib/wsl/lib`), then `cargo oxide run`; or pass `--arch <your arch>` explicitly. | Upstream: fail loudly instead of falling back when detection fails; until then the README warning box. | internal design notes; release rehearsal |
| 3 | **Mesh refit is host-side.** Every deforming-mesh frame downloads points (~51 KB at demo sizes) and re-uploads nodes (~0.5 MB). | Refit dominates the frame budget at large mesh sizes. | Sizes in this repo are chosen so it doesn't (predicates still pass, the mesh sim runs at full frame rate). | GPU refit: parent pointers + atomic arrival counters ([ROADMAP](../ROADMAP.md) Phase 3). | internal design notes §4.4; RESULTS.md mesh-sim cost note |
| 4 | **Optimizers run on the host** over downloaded gradients (~15 KB/iteration at `shape_fit` sizes). | Extra PCIe round trip per training iteration. | At these sizes it's noise (1.08 s for the full acceptance run — RESULTS.md, shape fitting). | GPU `adam_step` kernel behind the same `step()` signature ([ROADMAP](../ROADMAP.md) Phase 3). | `shannon-autodiff/src/optim.rs` doc-comment |
| 5 | **The tape is consumed per iteration and is not `Send`.** | You can't reuse a tape across iterations or record from multiple threads. | By design: `backward(self)` consuming the tape is what releases the borrows so the optimizer may mutate params. Rebuild the (cheap) tape each iteration. | A persistent/parallel tape is a future design question, not a patch. | internal design notes §4.1 |
| 6 | **Accumulated gradients are not bit-reproducible.** Float atomics commit in nondeterministic order. | Two identical runs differ in the last ulps; `==` comparisons on gradients fail spuriously. | All validation is relative-tolerance (1e-3 GPU-vs-CPU, 1e-4 parity), never exact equality. | None planned — this is inherent to atomic accumulation; deterministic reduction trees would trade speed. | internal design notes §5; RESULTS.md, shape fitting |
| 7 | **Mesh queries are unsigned** — no inside/outside sign. | You cannot tell penetration depth from proximity; naive collision response can pull particles *through* thin geometry. | Collision demos are restricted to geometry that guarantees sidedness (the heightfield argument in the mesh sims). | Signed closest-point via pseudonormals ([ROADMAP](../ROADMAP.md) Phase 3). | internal design notes §4.3 |
| 8 | **No blanket `AsKernelArg` impl** — custom by-value POD kernel params need a one-line registration in their defining crate. | Passing your own struct by value to a kernel fails to compile until you add `shannon_rt::impl_kernel_arg!(MyType);` (a blanket impl over `DeviceCopy` conflicts with the `&Array<T>` impls, E0119). | The one-line macro — see the tutorial's step 8. | A kernel registry ([ROADMAP](../ROADMAP.md) Phase 2) could hide it entirely. | `shannon-rt/src/launch.rs` doc-comment |
| 9 | **No runtime backend dispatch.** Call sites pick `kernels::x` (GPU) or `cpu::x` explicitly. | Switching backends means editing the call site (or keeping both, as the examples do). | The explicit-adapter design is a deliberate scope decision. | Registry-backed dispatch ([ROADMAP](../ROADMAP.md) Phase 2). | internal design notes |
| 10 | **Median-split BVH, leaf size 1, no SAH.** | Traversal throughput trails Warp's tuned LBVH: 4.5–5.8× on enumerate-all BVH queries at 16 384; the 1.45× mesh-cp gap at 16 384 is partly tree quality. | Adequate at 10k–100k prims; correctness is three-way validated regardless. | SAH/LBVH build + traversal-order upgrades ([ROADMAP](../ROADMAP.md) Phase 4). | RESULTS.md findings |
| 11 | **OBJ subset, genus-0 fitting.** Loader reads `v`/`f` lines only and rejects negative indices; Chamfer fits from a genus-0 source *drape over* concavities and holes (car windows, wheel wells). | Exotic OBJs fail to parse; fitted meshes look shrink-wrapped where the target is concave — correct behavior, surprising sight; highly non-convex targets can additionally stall in "tenting" minima (large faces bridging concavities at zero vertex-wise Chamfer cost). | Auto-normalization handles scale/position; `--smooth λ` (a per-iteration Laplacian shrink-wrap step, used by the car/cat/robot showcases at λ = 0.2) prevents tenting; pick targets accepting the draping caveat. | Out of scope for now; remeshing/topology ops unplanned. | internal design notes addendum; RESULTS.md showcase |
| 12 | **Workspace-wide `cargo test` cannot link example binaries.** The PTX-bundle symbol exists only under cargo-oxide's build. | `cargo test --workspace` fails at link time — looks like breakage, isn't. | The two canonical host-test commands in README § Testing. | Upstream (cargo-oxide test passthrough). | internal design notes §5.8 |
| 13 | **f32 only · one GPU · 1-D launch grids.** | No f64 kernels, no multi-device, no 2-D/3-D grid indexing. | Current contract; all demos are built inside it. | 2-D/3-D grids on the roadmap ([ROADMAP](../ROADMAP.md) Phase 4); f64/multi-GPU unplanned. | internal design notes |
